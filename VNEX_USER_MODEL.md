# VNEX User Model

This document defines the two main human roles VNEX is being designed for:

- `Creator`
- `Explorer`

It exists to prevent VNEX from being read too narrowly as:

- only a founder page
- only a builder feed
- only a software project board

VNEX should instead be read as a hybrid platform where work can exist before full public release.

## Core Position

VNEX is not only for people who publish.
It is also for people who discover, test, listen, respond, and enter early.

The platform becomes stronger only when both sides exist:

- people who make
- people who enter before full release

## Role 1: Creator

A `Creator` is any user who brings something into VNEX.

This can include:

- products
- AI tools
- music
- games
- media work
- research
- creative experiments
- hybrid systems

The creator does not need to be only a software builder.
That word is too narrow for the platform VNEX is meant to become.

### What A Creator Does

A creator should be able to:

- create a space
- create a work
- choose visibility
- post updates
- request testers or feedback
- open selective access
- move something from private to hybrid to public

### Why A Creator Uses VNEX

A creator uses VNEX because they may want:

- visibility without full exposure
- testing before release
- feedback in context
- early audience without losing control
- a premium presentation layer
- one place for products and creative work, not ten scattered platforms

### Creator Value

The core creator value of VNEX is:

- control
- presentation
- selective access
- progression toward release

## Role 2: Explorer

An `Explorer` is any user who enters VNEX to discover and interact with emerging work.

The explorer does not need to publish anything.

They may come to:

- discover products early
- test unreleased tools
- listen to unreleased music
- try in-progress games
- follow real development
- request access
- give feedback
- support creators before public launch

### What An Explorer Does

An explorer should be able to:

- browse spaces and works
- filter by interest
- enter hybrid experiences
- apply for access
- listen, view, test, or try previews
- leave useful feedback
- follow projects before release

### Why An Explorer Uses VNEX

An explorer uses VNEX because they want:

- early discovery
- access to rare or unfinished work
- better signal than a noisy public feed
- a premium environment for discovery
- direct contact with real creation, not only polished launch marketing

### Explorer Value

The core explorer value of VNEX is:

- discovery
- early access
- meaningful participation
- closeness to things before they become ordinary

## Where Creator And Explorer Meet

VNEX is valuable because these two roles meet in a controlled way.

The creator brings work.
The explorer brings attention, testing, feedback, and early participation.

The meeting point is not random social noise.
It is structured through:

- visibility control
- access control
- updates
- previews
- early release moments

## The VNEX Exchange

The practical exchange inside VNEX is:

- creators share selected reality
- explorers receive early access
- explorers return feedback, testing, attention, or support
- creators decide how much deeper to open the work

This is why `Hybrid` matters.

VNEX should not force everything into:

- fully private
- or fully public

It should make the middle state powerful.

## Official Visibility Model

The user model depends on three visibility states:

### Private

Only the creator or selected internal people can see the work.

### Hybrid

The work is visible in a controlled way.

The platform may show:

- that it exists
- what it is
- what stage it is in
- what is needed
- a preview or partial access

But not everything must be exposed.

### Public

The work is openly visible and fully released or broadly accessible.

## Official Interaction Model

Creators and explorers should interact through controlled actions, not chaotic social behavior.

Examples of official interaction:

- request access
- accept or decline access
- leave feedback
- follow a work
- join testing
- listen to preview content
- try a build
- respond to a creator request

## Why "Builder" Alone Is Not Enough

`Builder` may still appear in some older VNEX surfaces, but it should not be treated as the final public identity of the platform.

It is too narrow because VNEX is also meant for:

- musicians
- experimental creators
- media people
- AI makers
- product teams
- curious early users
- testers and discoverers

The stronger public framing is:

- creators and explorers
- work and access
- private, hybrid, public

## Product Reading Rule

Whenever VNEX is designed, written, or positioned publicly, the platform should be checked against this rule:

- does it help creators bring work into the world with control?
- does it help explorers discover and enter that work meaningfully?

If the answer is no, the design is drifting away from the real product.

## Summary

VNEX is not only a place to post.
It is a controlled environment where:

- creators introduce emerging work
- explorers enter before full release
- both sides meet through visibility, access, and progression

That is the real human model of the platform.
