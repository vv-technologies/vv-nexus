# VNEX Ownership And Access Rules

This document defines the core ownership and access rules VNEX should be built around.

It exists to protect:

- creators
- explorers
- the platform
- the distinction between visibility and transfer of rights

## Core Principle

Posting something on VNEX should not transfer ownership of that work to VNEX or to other users.

Visibility is not ownership.
Access is not ownership.
Preview is not transfer.
Testing is not transfer.

## Ownership Rule

The default platform rule should be:

- the creator keeps ownership of their own work
- VNEX receives only the limited rights needed to host, display, process, and distribute that work inside the platform according to the creator's selected settings and platform rules

This should apply unless a separate written agreement says otherwise.

## Platform License Rule

The platform should receive only a limited operational license, such as:

- host submitted content
- display it inside the platform
- show previews
- transmit it to approved users according to access settings
- process it for platform safety, moderation, indexing, and recommendation

The platform should not claim:

- full ownership
- blanket transfer of intellectual property
- unrestricted commercial exploitation outside the platform's operating purpose

## Visibility Does Not Equal Permission

Even when a work is visible, that does not automatically grant permission to:

- copy it
- re-upload it
- resell it
- redistribute it
- reverse engineer it
- use it commercially
- extract protected internal information

This distinction is essential to the VNEX model.

## Access Levels

VNEX should support access as a layered system.

### Private

Visible only to the creator and explicitly approved internal users.

### Hybrid

Visible in a controlled way.
The creator may expose:

- title
- summary
- stage
- needs
- preview
- selected media
- request entry point

But not all internal assets or details.

### Public

Broadly visible and intentionally opened by the creator.

Even here, public visibility should not erase the creator's ownership.

## Access Types

Works should support multiple access types, such as:

- open access
- request access
- invite only
- limited-seat access
- preview only
- testing access
- collaborator access

This lets creators control not only who sees a work, but how deeply they enter it.

## Sensitive Material Rule

Not all content should be delivered the same way.

Sensitive material may require:

- preview instead of download
- watermarked media
- limited runtime access
- hidden source files
- partial builds
- excerpted audio or video
- internal-only notes

This should be normal inside VNEX, not treated as an exception.

## Explorer Responsibilities

An explorer or tester should not treat access as a right to extract or republish.

By entering a work, they should agree that they may not:

- copy protected content without permission
- leak private or hybrid material
- redistribute files or captures
- impersonate ownership
- abuse testing access
- use private access to compete unfairly with the creator

## Creator Responsibilities

Creators should also follow platform rules.

They should not use VNEX to:

- upload content they do not control
- deceive users about ownership
- collect people under false pretenses
- misuse access requests
- expose third-party private information unlawfully

## Logging And Audit

VNEX should log sensitive access events where legally and technically appropriate.

This may include:

- access grants
- access requests
- content opens
- preview interactions
- download attempts
- moderation actions
- reports and resolutions

This helps protect both the platform and the creator.

## Enforcement Rule

If a user violates access or ownership rules, VNEX should be able to:

- remove access
- suspend the account
- remove content
- restrict features
- investigate reports
- support takedown actions

This is necessary for a serious premium platform.

## Summary

The correct VNEX ownership and access model is:

- creator owns the work
- platform operates the access layer
- visibility never equals ownership transfer
- hybrid access is controlled by design
- abuse can be logged, reviewed, and enforced
